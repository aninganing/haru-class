# 보안 점검

결과는 **실제로 악용 가능한 문제** 위주로 보고한다. 일반론 나열이 아니라 "어떤 요청을 보내면 무엇이 일어나는가"로 쓴다.
공격 재현은 로컬(localhost) 개발 환경에서만, 데이터를 망가뜨리지 않는 방식으로 한다.

## 1. 인증·인가

- [ ] 사용자 데이터를 다루는 모든 엔드포인트에 인증 가드가 있는가 (기본 거부, 공개 엔드포인트만 명시적으로 허용)
- [ ] **IDOR**: `GET/POST /bookings/:id/...`에서 `id`만 바꾸면 남의 예약을 보거나 취소할 수 있는가 → 조회 조건에 `userId`를 포함해야 한다
- [ ] 호스트 전용 기능(회차 생성, 예약자 목록)에 역할 검사가 있는가, 남의 클래스를 수정할 수 있는가
- [ ] JWT: 서명 알고리즘 고정, 만료 짧게, refresh 토큰 회전·폐기, 비밀키는 env
- [ ] 토큰은 httpOnly 쿠키(`access_token`)에만. `localStorage`, URL, 응답 본문에 노출되지 않는가

## 2. BFF 프록시 (`apps/web/src/app/api/[...path]/route.ts`)

- [ ] 프록시가 Nest의 **모든 경로**를 그대로 노출한다. 내부·관리자 전용 엔드포인트(웹훅, 큐 관리, health 상세)가 브라우저에서 호출 가능한가 → 공개할 경로 allowlist 또는 Nest 쪽 내부 경로 분리
- [ ] 경로 조작(`..`, 인코딩된 `%2e%2e`, `//`)으로 `API_URL` 밖이나 의도하지 않은 경로로 갈 수 있는가
- [ ] 클라이언트가 보낸 `authorization`, `cookie`, `x-forwarded-*` 헤더를 그대로 넘기지 않는가 (현재는 content-type만 전달 — 유지)
- [ ] 업스트림 에러 본문에 스택 트레이스·내부 정보가 섞여 나가지 않는가

## 3. 입력 검증과 주입

- [ ] 모든 body/query/param이 contracts zod 스키마를 거치는가 (`createZodDto`). `@Param('id')` 형식 검증
- [ ] Prisma raw SQL은 tagged template(`$queryRaw\`...${v}\``)만. `$queryRawUnsafe`/`$executeRawUnsafe` 금지
- [ ] 정렬·필터 필드를 사용자 입력으로 받으면 allowlist
- [ ] 숫자 범위(인원, 금액, 페이지 크기)에 상한이 있는가 — 큰 `take`로 DB를 긁는 요청 방지

## 4. 결제·예약 (돈이 걸린 로직)

- [ ] **결제 금액은 서버가 DB 가격으로 계산**하고, PG 승인 전에 요청 금액과 대조하는가 (클라이언트가 보낸 금액을 믿지 않음)
- [ ] 승인 요청은 `orderId` 멱등키로 한 번만 처리되는가, 같은 결제로 예약 두 개가 확정되지 않는가
- [ ] 웹훅: 서명/시크릿 검증, 재전송(replay) 방지, 프록시를 통해 브라우저에서 호출할 수 없는가
- [ ] 취소·환불이 예약 소유자만 가능하고, 환불 금액이 정책대로 서버에서 계산되는가
- [ ] 좌석 홀드를 대량으로 만들어 정원을 막는 공격(홀드 남용)에 사용자당 제한이 있는가

## 5. 웹 (Next)

- [ ] `dangerouslySetInnerHTML` 사용 여부. 사용자 입력(리뷰, 클래스 설명)은 텍스트로만 렌더링
- [ ] Server Action: 인자 검증(zod), 인증 확인을 액션 안에서 다시 한다 (페이지가 보호돼도 액션은 직접 호출 가능)
- [ ] 쿠키: `httpOnly`, `secure`(프로덕션), `sameSite=lax` 이상, 적절한 `path`·`maxAge`
- [ ] 리다이렉트 대상(`?next=`)이 외부 URL이면 거부 (open redirect)
- [ ] `NEXT_PUBLIC_*`에 비밀값이 없는가, 서버 전용 모듈이 클라이언트 번들에 섞이지 않는가 (`server-only`)

## 6. API 전반 (Nest)

- [ ] 보안 헤더(helmet), 요청 본문 크기 제한
- [ ] 로그인·예약·결제 엔드포인트 rate limit (`@nestjs/throttler`)
- [ ] 예외 필터가 프로덕션에서 내부 메시지·스택을 숨기는가
- [ ] 로그에 토큰, 전화번호, 결제 키 같은 개인정보·비밀값이 남지 않는가
- [ ] CORS는 열지 않는다 (BFF 구조). 열려 있으면 이유 확인

## 7. 비밀값과 공급망

```bash
git ls-files | grep -E '\.env($|\.)|\.pem$|id_rsa'        # 추적되면 안 됨
git grep -nE 'gh[pousr]_[A-Za-z0-9]{20,}|npm_[A-Za-z0-9]{20,}|sk-[A-Za-z0-9]{20,}|-----BEGIN' -- . ':!*.md'
pnpm audit --prod                                          # 알려진 취약점
```

- [ ] `.npmrc`에 토큰이 없는가 (토큰은 `~/.npmrc`나 CI 시크릿에만)
- [ ] `.env.example`에 실제 값이 없는가
- [ ] 새 의존성: 유지보수 상태, 다운로드 수, 설치 스크립트(`allowBuilds`에 추가할 때 이유 확인)

## 보고 형식

```
[치명|높음|중간|낮음] path:줄 — 한 줄 요약
  시나리오: 누가 어떤 요청을 보내면 → 무엇이 일어난다
  근거: 코드 인용 또는 재현 결과
  수정: 구체적인 방법
```

확인했지만 문제없는 항목은 "확인함"으로 짧게 묶는다. 아직 구현되지 않은 영역(예: 인증 전)은 "해당 없음 — 구현 시 확인"으로 표시한다.
